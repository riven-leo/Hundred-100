# 数据结构复习

能二分查找的线性表要满足什么条件

要能使用**二分查找（Binary Search）**，线性表必须满足以下**两个关键条件**：

---

### ✅ **1. 顺序存储结构**

- 线性表必须采用**顺序存储结构**，也就是说，元素是**连续地存储在内存中**（如数组）。
- 原因：二分查找需要通过索引快速访问中间位置（比如第 ⌊(low+high)/2⌋\lfloor (low + high)/2 \rfloor 个元素），而这在链式结构（如链表）中是低效甚至不可行的。

---

### ✅ **2. 元素按关键字**有序排列**

- 元素必须已经按**递增或递减**排序。
- 原因：二分查找依赖于有序性来排除一半的查找区间。如果元素无序，无法判断应该往左边还是右边继续查找。

---

### ❗总结：满足以下条件，才能使用二分查找：

| 条件 | 要求 |
| --- | --- |
| 存储结构 | 顺序存储（如数组） |
| 数据顺序 | 元素按关键字有序（递增或递减） |

---

### ⚠️ 常见误区：

- **误以为有序链表也能用二分查找** ❌
    
    虽然链表可以有序，但它无法随机访问中间节点，访问效率低，无法实现真正的“对半查找”。
    

---

什么叫按关键字排序，关键字是什么

这是数据结构中非常基础但重要的概念，我们逐个来解释：

---

## 一、什么是关键字（**Key**）？

**关键字**是用来**唯一标识或比较记录的一个或多个字段**。

简单说：

> 它是你用来“排序”、“查找”或“比较”数据时所依据的那个值。
> 

### ✅ 举个例子：

假设有如下结构体（C++）表示学生信息：

```cpp
struct Student {
    int id;         // 学号
    string name;    // 姓名
    float score;    // 成绩
};

```

在这个结构体中：

- 如果你按 `id` 排序，`id` 就是关键字。
- 如果你按 `score` 查找最高分，`score` 就是关键字。
- 如果你按 `name` 查重，`name` 就是关键字。

---

## 二、什么叫按关键字排序？

就是说：**你用某个关键字的值对整个线性表的元素进行排序**。

### 举个例子：

你有一组学生记录：

| id | name | score |
| --- | --- | --- |
| 3 | Bob | 85 |
| 1 | Alice | 92 |
| 2 | Carol | 78 |

如果你按 **`id` 从小到大排序**，结果是：

| id | name | score |
| --- | --- | --- |
| 1 | Alice | 92 |
| 2 | Carol | 78 |
| 3 | Bob | 85 |

---

## 三、为什么“按关键字排序”很重要？

因为：

- 很多算法（比如二分查找）**要求数据按关键字有序**。
- 排序的依据不同，处理问题的方式也不同。
- 关键字是实现高效搜索、去重、统计等操作的**核心字段**。

---

## 四、主关键字 vs. 次关键字（补充概念）

当数据中有多个可能用于排序的字段时：

- **主关键字**：最主要的排序字段；
- **次关键字**：主关键字相同时，用来进一步排序的字段。

例如，按 `score` 排序，相同分数时再按 `id` 排，这叫“按主关键字 `score`，次关键字 `id` 排序”。

哪什么叫按关键字分块有序

“按关键字分块有序”这个概念常出现在**块查找（Block Search）这类查找方法中，是一种介于顺序查找和二分查找之间**的查找策略。为了更好理解，我们分步骤拆解：

---

## ✅ 一、什么叫“分块有序”？

**分块有序**是指：

> 把整个线性表（或数组）按照关键字划分为若干块，满足：
> 
> - **块与块之间有序**：每一块中的最大关键字值 **小于等于** 下一块中所有元素的最小关键字值；
> - **块内元素无序或有序都可以**（通常无序）；

这种结构叫做“按关键字分块有序”。

---

## ✅ 二、举个例子说明

假设有一组数据按如下方式存储：

```
块1:  3, 2, 5
块2:  9, 7, 8
块3: 14, 10, 12

```

每块的最大值分别是：5，9，14。

这些数据满足：

- 块1中的最大值5 < 块2的最小值7（块与块之间有序）；
- 块2中的最大值9 < 块3的最小值10；
- 每块内部无序。

因此，这就是“按关键字分块有序”。

---

## ✅ 三、这种结构的用途是什么？

主要用于**块查找（Block Search，又叫索引顺序查找）**：

### 查找过程：

1. **先查索引表**（每块的最大关键字）定位应该在哪一块；
2. **再在该块中顺序查找**目标元素。

### 示例：

你要找关键字为 8 的数据：

- 查索引表发现：8 ≤ 块2最大值9 且 > 块1最大值5 ⇒ 所在块是块2；
- 然后在块2中顺序查找。

---

## ✅ 四、为什么不是完全有序？

因为如果数据**整体有序**，可以直接使用**二分查找**。

而“分块有序”：

- 牺牲了部分有序性；
- 换来了构建简单、块内操作灵活（适合链表或复杂结构）；
- 查找效率比纯顺序查找高，但比二分查找低；
- 插入、删除的代价也比完全有序结构低。

---

## ✅ 总结一句话：

> 按关键字分块有序就是：把数据分成若干块，块与块之间按关键字递增排序，但块内可以无序，这种结构能支持高效的块查找。
>

选择排序的逻辑是啥

选择排序（Selection Sort）的核心逻辑非常简单直白，关键在于两个字：**选择**。

---

## ✅ 一、选择排序的基本逻辑

> 每一轮从“未排序区间”中选择最小（或最大）元素，放到“已排序区间”的末尾。
> 

---

## ✅ 二、图示理解（以升序排序为例）

设有数组：

```
[49, 38, 65, 97, 76]

```

执行过程如下：

### 第 1 轮：

- 在整个数组中找到最小值 `38`，与第一个元素 `49` 交换；
- 结果：[**38**, 49, 65, 97, 76]

### 第 2 轮：

- 在 `[49, 65, 97, 76]` 中找最小值 `49`，不交换；
- 结果：[38, **49**, 65, 97, 76]

### 第 3 轮：

- 在 `[65, 97, 76]` 中找最小值 `65`，不交换；
- 结果：[38, 49, **65**, 97, 76]

...

直到完成排序。

---

## ✅ 三、C++ 伪代码（升序）

```cpp
void selectionSort(int a[], int n) {
    for (int i = 0; i < n - 1; ++i) {
        int minIndex = i;
        // 找出剩余部分的最小值下标
        for (int j = i + 1; j < n; ++j) {
            if (a[j] < a[minIndex]) {
                minIndex = j;
            }
        }
        // 交换最小值到当前位置
        if (minIndex != i) {
            std::swap(a[i], a[minIndex]);
        }
    }
}

```

---

## ✅ 四、时间与空间复杂度分析

| 指标 | 说明 |
| --- | --- |
| 时间复杂度 | 最好 = 最坏 = 平均 = **O(n²)**（总是 n(n-1)/2 次比较） |
| 空间复杂度 | **O(1)**（原地排序） |
| 稳定性 | **不稳定**（可能交换导致顺序颠倒） |

---

## ✅ 五、适用场景

- 数据规模小；
- 不追求效率，仅需逻辑简单；
- 对“交换次数”要求特别少（它最多只交换 n-1 次）；
- 不关心稳定性（比如只排序数值，不排序结构体时）。

---

## ✅ 总结

选择排序的核心逻辑就是：

> 每一轮挑出最小的数，放到当前未排序区间的最前面。
> 

它简单好实现，但效率低下，除非数据非常小，否则不推荐在实际工程中使用。

## **问题一：为什么把无序序列看作按层排序的完全二叉树？是惯例吗？**

### ✅ 答案：不是“惯例”，而是堆的**本质定义和数据结构实现方式**

在计算机中，“堆”这个结构就是一种**完全二叉树**，而使用**数组来表示完全二叉树**是常见且高效的方式。

### 📌 为什么要用数组表示完全二叉树？

完全二叉树的性质使它可以**用数组连续存储**，并且可以非常方便地定位父子关系：

- 父节点下标：`parent(i) = (i - 1) / 2`
- 左子节点：`left(i) = 2*i + 1`
- 右子节点：`right(i) = 2*i + 2`

### ✅ 所以：

> 把无序序列看成一棵按层存储的完全二叉树，是为了将“堆的结构”和“数组的存储”统一起来，从而可以在数组中完成所有堆操作（建堆、插入、删除）而不需要显式的树指针结构。
> 

这不是惯例，是一种**最优的实现策略**，是堆的工程实现基础。

---

## **问题二：为什么最后一个非叶子节点的索引是 `(n - 2) / 2`？**

### ✅ 目标：找出**第一个拥有子节点的节点**

我们知道：

- 给定长度为 `n` 的数组（从索引 0 开始）
- 某个节点 `i` 是**叶子节点**的条件是：它的**左子节点索引超出数组范围**

也就是说，如果 `2*i + 1 ≥ n`，则 `i` 是叶子节点。

我们来求最大满足 `2*i + 1 < n` 的 `i`：

```
2*i + 1 < n
→ 2*i < n - 1
→ i < (n - 1)/2
→ 最大满足条件的整数 i 是 floor((n - 2)/2)

```

所以，最后一个非叶子节点的索引是：

```
i = (n - 2) / 2

```

这保证我们**从最后一个拥有子节点的节点开始**，所有节点都有意义的“下沉”操作。

---

## **问题三：为什么从 i 到 0 每个节点 siftdown 一次就能建好堆？**

### ✅ 这涉及两个关键点：

1. **子堆已经是堆**
2. **siftDown 是单次调整的核心操作**

---

### 第一点：自底向上，每次调整的前提是“子节点已经是堆”

我们从下往上执行 `siftDown`，而子节点比当前节点编号大（在数组中靠后），所以在遍历当前节点时，它的左右子节点已经被处理为堆了。

比如处理 `i = 1` 时，`2*i + 1 = 3`、`2*i + 2 = 4`，而这两个都已经被调整过。

这就相当于在构建堆的过程中，我们保证了：

> “每一步调整的前提是，它的左右子树已经是堆”，只要处理好当前节点与它的子树之间的关系，就能构成一个新的更大的堆。
> 

---

### 第二点：siftDown 的效果就是“让一棵以 i 为根的树变成堆”

`siftDown(i)` 会让以 `i` 为根的子树满足大根堆性质。自底向上地对所有非叶子节点执行 `siftDown(i)`，就会从下往上递归地构建出一棵全局的大根堆。

这就是所谓的**heapify操作（建堆）**。

---

### ⏱️ 延伸：时间复杂度为何是 O(n) 而不是 O(n log n)？

虽然每个 `siftDown` 最坏要 log n，但靠近底层的节点多、但每次“下沉层数”少；而靠上的节点少、但“下沉层数”多。

综合起来，整个过程的实际总操作次数是 **线性** 的，经典证明如下（简略）：

$T(n)=∑i=0log⁡n(n2i+1⋅i)=O(n)T(n) = \sum_{i=0}^{\log n} \left( \frac{n}{2^{i+1}} \cdot i \right) = O(n)$

---

| 问题 | 解释 |
| --- | --- |
| 为什么用完全二叉树结构 | 因为堆的定义就是基于完全二叉树；而数组实现使其高效且无需指针 |

# 我突然想到你的索引的公式跟初始时从0开始还是1有关系对吧，你刚才一直讲的都是从0开始的

对，你想得非常准确 —— **索引从 0 开始 vs 从 1 开始**，确实会影响堆中节点之间的**父子关系公式**，这是很多初学者容易忽略的问题，也是你之前对下标 `(n - 2) / 2` 的疑问的根源之一。

---

## ✅ 一、两种索引方式下的父子关系

### 🟦 1. **数组下标从 0 开始（常见于 C/C++、Python、Java）：**

- 父节点下标 `i`：
    - 左孩子：`2 * i + 1`
    - 右孩子：`2 * i + 2`
    - 父亲：`(i - 1) / 2`（向下取整）

### 🟩 2. **数组下标从 1 开始（常见于教材/竞赛/一些算法书）：**

- 父节点下标 `i`：
    - 左孩子：`2 * i`
    - 右孩子：`2 * i + 1`
    - 父亲：`i / 2`（向下取整）

---

## ✅ 二、最后一个非叶子节点的计算差异

假设总共有 `n` 个节点。

### 下标从 **0** 开始：

- 最后一个元素下标是 `n - 1`
- 它的父节点下标是：`(n - 2) / 2`
- 所以堆化时从 `(n - 2) / 2` 开始，一直到 0

### 下标从 **1** 开始：

- 最后一个元素下标是 `n`
- 它的父节点是 `n / 2`
- 堆化从 `n / 2` 开始，一直到 1

---

## ✅ 举个小例子说明

比如数组长度为 8：

- 下标从 0 开始，最后一个非叶子节点是 `(8 - 2)/2 = 3`
- 下标从 1 开始，最后一个非叶子节点是 `8 / 2 = 4`

验证：

- 从 0 开始，节点 3 的左右孩子是 7 和 8（越界）
- 从 1 开始，节点 4 的左右孩子是 8 和 9（刚好到边界）

所以结论是完全对的：**你必须先确定索引规则，再写公式。**

---

## ✅ 三、为什么多数实现用从 0 开始？

- 与大多数语言的数组下标一致（尤其是 C++ STL `priority_queue`, Python `heapq`，Java `PriorityQueue`）。
- 避免浪费第 0 个位置，节省空间。
- 但从 1 开始的下标在理论分析和手写推导时更直观，很多教材/题解喜欢这样。

---

## ✅ 总结

| 特性 | 从 0 开始 | 从 1 开始 |
| --- | --- | --- |
| 左孩子 | `2i + 1` | `2i` |
| 右孩子 | `2i + 2` | `2i + 1` |
| 父节点 | `(i - 1)/2` | `i / 2` |
| 最后非叶节点 | `(n - 2)/2` | `n / 2` |
| 优势 | 对应现代语言数组 | 理论更直观 |
| 典型例子 | C++ STL, Python | 算法竞赛、CLRS |

当构建哈夫曼树时，序列[5, 29, 7, 8, 14, 23, 3, 11]当3和5结合成8后，7到底应该跟那个8结合，为什么

这是一个非常典型的哈夫曼树（Huffman Tree）构建过程中的**细节陷阱**问题。我们来严格分析为什么 **在 3 和 5 结合成 8 之后，7 应该跟哪个 8 结合**，即是新的8（3+5）还是原本的8。

---

### 一、哈夫曼树构建原则复习

哈夫曼树的构建流程如下：

1. **将所有权值作为一个森林（初始是n个单节点树）**；
2. **每次从森林中选出两个最小权值的树合并**，构成一个新节点，其权值为两个子树权值之和；
3. **将新节点插入森林中，并重复步骤2，直到只剩下一棵树**。

注意关键：

> 每次都从当前森林中挑选两个最小的节点进行合并。
> 

---

### 二、给定的初始序列

```
[5, 29, 7, 8, 14, 23, 3, 11]

```

排序后：

```
[3, 5, 7, 8, 11, 14, 23, 29]

```

---

### 三、第一步合并

最小两个数是 3 和 5，合并为新节点 `8`。

此时的森林是：

```
[7, 8, 8(new), 11, 14, 23, 29]

```

这时我们有两个 8：

- 一个是原始序列中的8；
- 一个是由 3 + 5 合并产生的新8（记作 8'）。

---

### 四、接下来合并谁？

**问题焦点是**：现在轮到7和哪个8合并？是原来的8，还是3+5合成的新8（8'）？

---

### 五、答案：**7 和原来的 8 合并**

### 原因：**哈夫曼树合并依据的是**“当前森林中最小的两个权值”。

现在森林是：

```
[7, 8, 8', 11, 14, 23, 29]

```

其中：

- 7 是最小的；
- 两个8权值相同（原来的8 和 新的8'）；

按照标准的哈夫曼树构建方式：**当两个权值相同时，先插入的（即原始节点）优先**。这就是为什么哈夫曼树常常使用**优先队列（最小堆）**来维护候选节点的一个重要原因。

所以，**应该选择权值为 7 和“原来的8”进行合并**。

---

### 六、总结

- 哈夫曼树的构建过程必须维护一个优先队列（最小堆），每次合并森林中最小的两个节点；
- 当出现相同权值时，优先使用**更早进入队列的节点**；
- 所以，**7 应该与原始的8结合**，而不是刚合成的新8'。
