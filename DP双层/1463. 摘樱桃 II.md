# 1463. 摘樱桃 II

## 题目模型

两个机器人从第一行两端出发，每走一行，各自的列坐标都可以变化 `-1、0、+1`。求走到最后一行最多能收集多少樱桃；如果两个机器人落在同一格，该格只能计算一次。

单个机器人只需要“行 + 列”描述状态，两个机器人同时移动则需要“行 + 两个列坐标”。这就是双主体 DP 的典型信号。

## 思路

代码采用自底向上的反向 DP，并用滚动数组压缩行这一维。

令 `pre[j+1][k+1]` 表示下一行开始，两个机器人位于列 `j、k` 时最多还能取得的樱桃数。计算当前行 `(i,j,k)` 时，两个机器人下一步各有 3 种走法，因此共有 9 种列组合；取 9 个后继状态的最大值，再加当前两个格子的樱桃。

由于当前实现只枚举 `j < k`，两个机器人不会重复计算同一个格子，所以直接加 `grid[i][j] + grid[i][k]`。

## 关键逻辑

- `j` 的可达范围是 `[0, min(n-1,i)]`：左侧机器人走了 `i` 行，最多向右移动 `i` 列。
- `k` 的可达范围从 `max(j+1,n-1-i)` 开始：既满足右侧机器人的可达范围，也保持 `j < k`。
- 数组左右各补一圈，真实列 `j` 映射到下标 `j+1`，这样 9 个转移不需要逐个判断越界。
- 当前行算完后 `swap(pre,cur)`，让当前结果成为上一行计算时的“下一行答案”。
- 最终 `pre[1][n]` 对应第一行的列 `0` 和列 `n-1`。

## 关键数据结构

- `pre`：已经算完的下一行状态。
- `cur`：正在计算的当前行状态。
- 二维数组下标 `(j,k)`：同时表示两个机器人的位置，这是“双层”的核心，而不是简单地把两个独立 DP 相加。

## 复杂度

- 时间复杂度：`O(m*n^2)`，每个双列状态检查常数个（9 个）后继。
- 空间复杂度：`O(n^2)`，通过滚动数组省去行维度。

## 易错点

1. 两个机器人并不独立；它们可能访问同一格，标准状态必须同时包含两个列坐标。
2. 使用补边数组后，真实列与数组下标始终相差 1。
3. `swap` 后不要误把 `cur` 当成下一行；语义已经交换。
4. 本实现利用题目中樱桃数非负并限制 `j < k`。若题目允许负数或必须支持两机器人重合，应使用负无穷初始化，并在 `j == k` 时只加一次。
