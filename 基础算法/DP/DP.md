## 动态规划前置

原问题会分解成相同的子问题，且子问题有重复计算（最优子问题、重复子问题）

*怎么想到动态规划？*

动态规划通常不是从“我想到了一个规则”(贪心思维具体经验规则)演变来的，而是从“我把所有可能操作都试一遍”的暴力递归演变来的。

暴力思路问题依次问：

1. 当前有哪些可能选择？->题目会给
2. 每个选择之后，是否变成一个规模更小的同类问题?->*这里比较关键，子问题要分清楚*
3. 描述这个子问题需要哪些变量？
4. 不同选择是否会到达相同的子问题？->是否子问题重复计算
5. 原问题的最优答案，是否等于若干子问题答案加上当前代价后取 min 或 max？

完整的演变过程如下：

枚举所有操作

→ 写成递归

→ 发现相同子问题重复计算

→ 保存子问题答案

→ 动态规划

1. 定义状态->dp[i][j] = 存什么
dp[i][j]表示小状态，会有初态，终态dp[n][m]即原问题
存的东西通常与原问题要求的东西是一样的(如该题就是需要操作的次数)
2. 需要写出状态转换公式

## 思路

最暴力的思路是我当前不知道进行那个操作最优，**从开头开始或从末尾开始**那我就每个操作都试一下，最看那个操作次数最少->总尝试数 = 操作的种类3×从头开始

这里暴力搜索也是有技巧在其中的

**特殊**

例如:word1 = abc, word2 = bca;

从开头开始比较，

如果..., 直接匹配

a 和 b 不匹配

1. 删除a, 剩下需要解决bc->bca，发现是一个更小范围的编辑距离问题，也就是子问题
2. 在a前插入b, 为了匹配word2的b，剩下需要解决 *abc->ca*, 可以发现这里的不同，因为已经匹配上了b, 子问题变成word2减少一个需要匹配的字符，而不是变成*babc->bca*
3. 把a替换成b, 剩下需要解决bc->ca
最终需要的操作次数 = 1 + min{
bc->bca, 删除a后
abc->ca, 在a前插入b后
bc->ca, 把a替换成b后
}这三个子问题中需要步数最少的那一个

**一般**

*后缀递归形式*

定义f(i,j)为把 word1 从下标 i 开始的剩余部分，变成 word2 从下标 j 开始的剩余部分，最少需要多少步

从word1[i],word2[j]开始,

if word1[i] == word2[j], f(i,j) = f(i+1,j+1)(子问题)

if word1[i] != word2[j]

分三种情况

f(i,j) = 1 + min{

f(i+1,j) 删除w1[i]

f(i,j+1) 在w1[i]前面插入w2[j]

f(i+1,j+1) 替换w1[i]为w2[j]

}

直观上可以察觉子问题有重复计算，所以存储f(i,j)的结果，这就是记忆化搜索，也就是动态规划

## 174 地下城游戏

## 思路

我只想清楚了，单条路径如何补血，但是代码实现还有问题

你当前的思路可以概括为一种“正向双状态 DP”。

*一、你的思路是什么*

你从起点走向终点，对每个格子维护两个信息：

dp[i][j]表示到达 (i,j) 时，骑士至少需要多少初始血量。

cur[i+1][j+1]表示采用 dp[i][j] 所对应的路径，到达 (i,j) 后还剩多少血量。

*对于dp[i][0],dp[0][j]更新逻辑*

对于一条已经确定的路径，你的更新逻辑是：

新的当前血量 = 原来的当前血量 + 当前格子的数值

如果新的当前血量小于等于 0，说明初始血量不够，于是补充：

需要补充的血量 = 1 - 新的当前血量

然后：

最小初始血量 += 补充量

当前剩余血量 = 1

第一行和第一列只有唯一的路径，因此直接沿着上一格更新。

*对于dp[i][j]*

对于内部格子，你分别计算：

从左边过来的方案；

从上边过来的方案；

然后选择所需初始血量较小的方案：dp[i][j] = min(left, up);

*模拟思路*

这个思路的核心可以写成：

正向前进

→ 模拟路径上的血量变化

→ 血量不够时增加初始血量

→ 在汇合点选择初始血量要求较小的路径

其中，“给定一条固定路径，计算它最少需要多少初始血量”这一部分是正确的。

**然而正向DP（从起点开始到达每一个点需要多少血量）做该题状态很复杂，要存储的东西过多，所以应思考反向DP（从每个点到达终点需要多少血量 ）**

状态dp[i][j] = (i,j) location to end need min points

//初始化

dp[n-1][m-1] = max(1, 1 - D[n-1][m-1]);

//先上后左再求中间依次DP

//DP规则是当前位置的最少次数dp = 右和下位置最少次数dp的min者 + 在当前位置能活下来的最少血量

for (int i = n-2; i >= 0; i--) {

dp[i][m-1] = max(1, dp[i+1][m-1] - D[i][m-1]);

for (int j = m-2; j >= 0; j--) {

dp[n-1][j] = max(1, dp[n-1][j+1] - D[n-1][j]);

dp[i][j] = max(1, min(dp[i+1][j], dp[i][j+1]) - D[i][j]);

}

}

return dp[0][0];

你这次的问题属于典型的边界结构错误，不是转移方程错误。检查二维 DP 时，可以固定测试这四种形状：

1 × 1

1 × m

n × 1

n × m

你的代码正是在 1 × m 上暴露了问题。
