# new和时间复杂度

Status: Not started

在C++中，`new`操作符返回的是一个指向新分配内存的指针，具体行为如下：

---

1. 基本返回类型
- 对于单个对象：`new Type` 返回 `Type*` 指针
    
    示例：`int* p = new int;`
    
    → 指针 `p` 指向新分配的整型内存空间。
    
- 对于对象数组：`new Type[n]` 返回 `Type*` 指针
    
    示例：`int* arr = new int[10];`
    
    → 指针 `arr` 指向动态分配的数组首地址。
    

---

1. 构造行为的区别
- 内置类型（如 `int`、`double`）：
    
    `new` 会分配内存但不初始化值（除非显式初始化，如 `new int(5)`）。
    
- 自定义类对象：
    
    `new ClassName` 会调用类的构造函数完成初始化。
    

---

1. 内存分配失败的策略
- 默认行为：内存不足时，`new` 会抛出 `std::bad_alloc` 异常。
- 无异常版本：使用 `new (std::nothrow) Type` 时，失败返回 `nullptr`。
示例：
    
    ```cpp
    int* p = new (std::nothrow) int;
    if (p == nullptr) { /* 处理失败 */ }
    
    ```
    

---

1. 注意事项
- 必须配对释放：
    - 单个对象 → `delete ptr;`
    - 数组 → `delete[] ptr;`
    错误使用会导致未定义行为（如内存泄漏或崩溃）。
- 优先使用智能指针（如 `std::unique_ptr`、`std::shared_ptr`）：
    
    ```cpp
    auto p = std::make_unique<int>(10);  // C++14+ 推荐方式
    
    ```
    
    避免手动管理内存，减少泄漏风险。
    

---

1. 与其他语言的对比
- 与C的`malloc`区别：`new` 不仅分配内存，还调用构造函数；`malloc` 仅分配内存（需手动初始化）。
- 与Java/C#对比：
这些语言的 `new` 返回对象引用，而C++返回指针，需显式管理生命周期。

---

总结
`new` 的核心作用是动态分配内存并，但需谨慎处理释放和 异常。现代C++更推荐使用智能指针或容器（如 `std::vector`）来替代裸指针操作。 

估算算法的平均时间复杂度可以通过以下技巧快速判断，避免繁琐的数学推导：

---

### **1. 观察操作的核心模式**

- **线性遍历**：如果操作涉及遍历数据结构的 **一半元素**（如顺序表插入、删除中间元素），平均时间复杂度通常为 **O(n)**。
- **分治/二分**：若每次操作将数据规模 **减半**（如二分查找、归并排序），时间复杂度一般为 **O(log n)**。
- **嵌套循环**：循环层数直接决定复杂度。例如双重循环遍历二维数组，时间复杂度为 **O(n²)**。

---

### **2. 平均情况的简化计算**

假设操作位置是 **均匀随机分布** 的：

- **顺序表插入**：向长度为 `n` 的顺序表中插入元素时，有 `n+1` 个可能的位置（包括头尾）。
    - **移动元素次数的期望值** = `(0 + 1 + 2 + ... + n) / (n+1)` ≈ `n/2`
    - 因此平均时间复杂度为 **O(n)**（系数 `1/2` 在大 O 中省略）。

---

### **3. 经验法则**

- **线性结构**（数组、链表）：插入/删除平均需操作 **一半元素** → **O(n)**。
- **哈希表**：冲突较少时，插入/查找平均为 **O(1)**（均匀哈希假设）。
- **树结构**（平衡二叉搜索树）：每次操作缩小一半搜索范围 → **O(log n)**。

---

### **4. 快速判断步骤**

1. **识别核心操作**：找到算法中重复执行的基本操作（如元素移动、比较）。
2. **分析循环次数**：观察循环与输入规模 `n` 的关系（单层循环 → O(n)，双重循环 → O(n²)）。
3. **假设均匀分布**：若操作位置随机，用期望值简化计算（如取中间值 `n/2`）。
4. **对比常见模式**：直接匹配经典算法的时间复杂度（如排序、查找算法）。

---

### **示例：顺序表插入的快速分析**

1. **核心操作**：将插入位置后的元素逐个后移。
2. **平均情况假设**：插入位置在 `0` 到 `n` 之间均匀分布。
3. **估算移动次数**：平均需移动 `n/2` 个元素。
4. **结论**：时间复杂度为 **O(n)**。

---

### **注意事项**

- **大 O 表示法忽略系数**：即使平均移动次数是 `n/2`，仍简化为 **O(n)**。
- **极端情况**：若插入末尾（移动 0 次）或头部（移动 `n` 次），时间复杂度仍为 **O(n)**。
- **严谨场景**：需严格计算期望值（如求和公式），但快速估算时可直接取中间值。

这种方法能覆盖大多数场景，适合面试、考试或快速分析！
