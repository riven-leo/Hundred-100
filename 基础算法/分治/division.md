# eg:109有序链表转化**平衡**二叉**搜索**树

## 概念补充：

平衡：任何节点的两个子树的高度差（平衡因子）最多为 1

高度：一个节点到它最远的子孙节点，中间跨越了几层，它的高度就是多少

## 思路

1. 输入：链表头节点；输出：树节点
2. 这道题要求：具体构造方案
3. 数据规模允许的复杂度：int（我认为是）
4. 最**暴力**的方法是什么：~~找到最中间的节点，然后左边右边一边一个，确保左右子树高度差最多为1~~ -> 找到最中间的节点，左半部分整体负责构造左子树；右半部分整体负责构造右子树，确保左右子树高度差最多为1

**怎么想到构造子树来解决问题的？**

因为二叉树本身就是递归定义的，一棵二叉树可以定义为：一个根节点，加上一棵左二叉树和一棵右二叉树，所以自然的想到，想要整棵树都是平衡二叉树，要保证左右两颗子树都是平衡二叉树

**为什么要找最中间的节点呢？**

尽量保证左右两边节点相同，然后又很自然的想到的，偶数节点和奇数节点数的区别

如果是奇数节点，取最中间节点

如果是偶数节点，根据c语言除法向下取整，舍去小数，所以取平分后左边最后一个节点为中间节点

**怎么确保高度差为1呢？**

只要每次取中点为子树根，这就很天然的确保了左右子树高度差最多为1

-->这个通过解决子树的问题从而递归间接解决大树的问题的方法就是——分治法

## 一、通过数组的下标找中间节点

**怎么知道数组下标找到根节点之后干什么？**

人类直观做法就是平分后开始左右一边一个节点，也就是构造。

递归实现构造，build函数，左边构造右边构造，怎么想到递归构造的呢，因为树问题，天然符合子问题和原问题相同，都是构造问题，所以从解决子问题递归回去从而解决原问题，然后极限子问题就是递归的出口，也就是当链表里没有元素的时候（**l = r错误，l>r正确，前者表示恰好还剩最后一个元素**）

### 思路

链表->数组，取数组中间下标（mid = left + right >> 1）为根节点，然后递归构造子树

### 伪代码

for head

num.push_back(head->val)

start build tree

TreeNode *build(num, left, right) {
if left > right
return nullptr;
mid = left + right >> 1;
TreeNode* root(num[mid]);
root->left = build(left, mid-1);
root->right = build(mid+1, right);
}

## 二、快慢指针访问链表找中间节点

fast move 2n steps, slow move n steps, Δ = n steps; 所以当fast走n步时，slow走了n/2步，两者相距了n/2，slow所在的位置就在中点

**快慢指针提供三类信息：**

某个指针走到终点(**end, nullptr**)时，另一个指针走到了哪里；

两个指针是否会相遇；

两个指针之间能否保持某个固定距离。

### 思路

**怎么获得尾部呢？**

因为链表获取后继很简单，而难以获取前驱，所以build(head, nullptr),左闭右开，对应[head,end)

构造平衡树(**知道头尾位置**)，递归构造，每次快慢指针找到根节点，左右构造平衡子树，出口为链表为空（**head == nullptr错，head == end正确，因为[head,end)左闭右开，当head==end的时候取不到，则没有元素了**）

### 模板伪代码

```c
ListNode* slow = head;
ListNode* fast = head;

while(fast != nullptr
    and fast->next != nullptr)
    slow = slow->next;
    fast = fast->next->next;
```

分治法的本质：因为子问题和原问题相同，从而通过调用相同函数解决子问题从而递归解决原问题

# 思路

~~二维数组(row, col)~~

~~query_row -> row, query_glass = col~~

这里的问题就在于找不到行之间的映射关系

solve (row, col)

need solve (row-1, col-1) and (row-1, col)

每一层瓶收到的来自上层的酒的量p

P[row][col] = P[row-1][col] + P[row][col-1];

when poured=3, P[0][0] = 1, P[1][0] = 1, P[1][1] = 1;

等待或判断上层酒杯是否满||一瓶一瓶倒，是没有必要的—>

**核心思想：把所有酒都放在最顶层，让它自己溢出**

数学递推公式:

P[row][glass] = (P[row-1][glass]-1)/2 + (P[row-1][glass-1]-1)/2

**进入循环每一步做什么？**

*为什么要进入循环？什么时候进入循环*->实现滚动数组；模拟溢出到下一层这个动作，也可以得知此处需要循环？

*为什么遍历query_glass或next.size()都是错误，遍历cur.size()正确？*->因为从下一层角度思考（确实是数学递推公式思考方式--An+1=f(An)）会在第一个和最后一个酒瓶出现上一层酒的来源只有一个酒瓶（边界问题），所以从上一层的角度思考，每个酒瓶左右都给酒

第一层循环，遍历query_row行，从而获得下一行的大小

第二层循环，遍历cur.size(), 计算这一行所有瓶子里的酒量

循环结束后nextRow更新为curRow

**什么是滚动数组？为什么会想到滚动数组？**

->用两个数组只存储当前行和下一行的数据，通过循环将下一行更新为当前行，再进行下一步操作；这样**下一层的值由上层计算得出的题目**

在写动态规划（DP）或者模拟题时，通常的进化路线是：暴力三维/二维 \rightarrow 发现浪费 \rightarrow 降维压缩（滚动数组）。

进化步骤：首先思考用一个完整的二维数组去存储，发现行的映射很困难，舍弃这种想法，但是可以想到依旧用数组，则每行用一个数组去存储，随后思考怎么填入数据，发现当前行的数据可以决定下一行的数据，从而优化保留两个数组curRow和nextRow,通过cur获得next后，再通过next去获得下一个next，由此可知这里有个循环

**为什么最后要取数组值和1中的更小值？**

因为当poured很大且query的酒瓶位置靠近上层的时候，有可能query的酒瓶里的酒是大于1的

**时间复杂度巩固：**

大 O 表示法通常关注的是上界（最坏情况）

算法执行过程中，最主要的操作执行了多少次(最坏情况)，通常直接数循环执行了多少次。

*为什么分析复杂度经常数"访问次数"？*

因为很多基本操作都是 O(1)，那么真正拉开算法差距的是：这些 O(1) 操作执行了多少次。交换操作(swap(a,b))或动指针操作(cur = cur->next) 都是O(1)

对于不同的数据结构，这个"最贵资源"不同。

数组：通常数元素访问次数。

链表：通常数节点访问次数。

图：通常数边和点访问次数。

树：通常数节点访问次数。

分治时间复杂度O(N*logk)，N链表总节点，k链表总数；在链表合并中，每个节点在分治的情况下需要访问logk次(需要进行logk层操作)

分治是把需要二分的东西每次变成原来的一半，然后再进行操作，可以让重复执行的操作（例如访问）从k^2优化为logk

二分不是分治

以后遇到任何分治题，都可以问自己两个问题：每一层总代价是多少？一共有多少层？然后直接相乘
