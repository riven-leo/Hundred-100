# 460. LFU 缓存

## 题目模型

缓存满时优先淘汰访问频率最低的键；若频率相同，再淘汰最久未使用的键。`get` 和 `put` 都要求平均 `O(1)`。

一个哈希表只能快速找到键，却不能同时维护“最低频率”和“同频率内的最近使用顺序”，所以需要哈希表与双向链表组合。

## 思路

把所有条目按访问频率分桶：每个频率对应一条双向链表。链表头是该频率下最近使用的条目，链表尾是最久未使用的条目。

再用两个映射和一个变量完成所有操作：

- `key_to_iter`：由 key 直接定位到链表节点；
- `freq_to_list`：由频率定位到该频率的 LRU 链表；
- `min_freq`：始终指向当前最小频率。

访问或更新一个已有键时，把节点从旧频率链表摘下，频率加一，再插入新频率链表头部。

## 关键逻辑

- `move` 必须先复制节点内容，再删除旧迭代器，因为删除后迭代器失效。
- 若被移走的节点使 `min_freq` 对应链表变空，则 `min_freq++`。
- 淘汰时从 `freq_to_list[min_freq].back()` 删除，满足“最低频率中的最久未使用”。
- 新键频率为 1，插入频率 1 的链表头，并把 `min_freq` 重置为 1。
- 更新已有 key 的 value 也算一次访问，因此需要调用 `move`。

## 关键数据结构

- `list<Entry>`：双向链表支持已知迭代器位置的 `O(1)` 删除，并维护同频率的 LRU 顺序。
- `unordered_map<int,list<Entry>::iterator>`：key 到节点位置。
- `unordered_map<int,list<Entry>>`：频率到链表。

## 复杂度

- `get`：平均 `O(1)`。
- `put`：平均 `O(1)`。
- 空间复杂度：`O(capacity)`；当前实现为便于理解，不主动删除已经为空的频率链表桶。

## 易错点

1. `list` 删除节点后迭代器失效，必须立即更新 `key_to_iter`。
2. 不能只维护频率；同频率还要维护 LRU 次序。
3. 淘汰节点时既要从链表删除，也要从 key 映射删除。
4. 容量为 0 时，`put` 应直接返回；否则对空链表调用 `back()` 会出错。当前代码依赖容量为正的使用前提。
5. 源文件使用了 `list`，应确保包含 `<list>` 头文件。
