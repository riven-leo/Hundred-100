# 哈希表题型：把需要反复查找的关系变成键

## 哈希表真正解决什么问题

哈希表不是一种完整算法，而是把“按某个特征查找、计数或定位”的平均成本降到 `O(1)`。使用前先回答：

> 我希望以后拿什么信息当 key，立刻找到什么 value？

常见映射包括：

- 值 → 出现次数；
- 特征 → 同类对象数量；
- key → 数据结构中的节点位置；
- 状态 → 是否出现过；
- 边界点 → 出现奇偶性。

## 三类可迁移模型

### 1. 计数与分组

把对象转换成统一特征，再用 `feature -> count` 分组。例如固定一个点后，把其他点的方向约分为 `(dy,dx)`；同键对象属于同一类。

难点通常不在哈希表，而在**键的规范化**：浮点精度、正负号、顺序、重复元素都必须处理。

### 2. 频次表 + 滑动窗口

目标表 `need` 保存要求，窗口表 `window` 保存当前拥有量：

- 新元素合法：加入窗口；
- 某元素超量：移动左端直到重新合法；
- 新元素完全非法：清空或跨过失效段；
- 所有频次满足：记录答案。

这适合字母异位词、固定长度单词串联、覆盖子串等问题。

### 3. 哈希表 + 有序结构

哈希表负责“找到”，链表、堆、集合负责“维护顺序或优先级”。LFU 中哈希表定位节点，双向链表维护同频率的 LRU 顺序；只用其中一种结构无法同时达到要求。

## 抵消思想

若内部元素应成对出现，可以用集合的插入/删除或计数奇偶性让内部部分抵消，只留下边界。例如矩形拼接的顶点奇偶性、无向边配对等。此时还常需面积或数量守恒作为第二个独立条件。

## 如何设计可靠的 key

1. 相等对象必须生成完全相同的 key。
2. 不同对象应尽量避免碰成同一 key。
3. 分数、斜率等精确关系优先用约分后的整数，不用浮点数。
4. 无序组合先排序或统一方向。
5. 组合键可用 `pair` 加自定义哈希、编码整数或稳定字符串。

## 易错点检查表

1. 使用 `operator[]` 是否会意外插入默认值？
2. 清空窗口时，计数、边界和辅助变量是否一起重置？
3. 删除链表节点后，保存的迭代器是否失效？
4. `unordered_map` 的平均 `O(1)` 是否足够，还是需要有序遍历而改用 `map`？
5. 自定义键是否完成了约分、符号和边界规范化？
6. 哈希表只是加速查询，题目的顺序、区间或优先级是否还需要另一种数据结构？
